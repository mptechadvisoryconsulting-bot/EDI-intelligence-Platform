# EDI Lifecycle Documentation

`PRD.md` is the version 2.3 operations and software blueprint. It begins with how the EDI department works, then defines the reusable Transaction Interface Library, structured customer requirements, Production, screens, workflows, data model, APIs, architecture, security, roadmap, and acceptance criteria.

`Codex-Development-Guide.md` contains mandatory implementation constraints for AI-assisted development.

`Architectural-Refactor-Specification.md` is the governing target architecture for replacing the legacy Project aggregate with permanent Trading Partner Transactions. New domain work must follow it.

Supporting specifications:

- Architectural Refactor Specification
- Database and migrations
- Workflows and status transitions
- Role and permission matrix
- API contracts
- Security and operations
- UI standards and wireframes
- Reporting catalog
- Roadmap and release plan

No supporting document may silently contradict the blueprint. Conflicts require an explicit product decision and version update.
